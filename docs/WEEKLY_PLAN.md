# 주차별 개발 계획

> **v0.1 / 제안 초안 (2026-09-08)**  
> [프로젝트 개요](../README.md)  
> 실제 시작일·마감일·담당자는 미정이며, 착수 시점부터 8주를 가정합니다. 모든 개발 작업은 계획 상태입니다. 보드·시나리오·통신 방식과 정량 목표를 1주차에 확정한 뒤 일정과 범위를 조정합니다.

## 1주차 — 요구사항 및 설계 기준 확정

- 최소 시연 시나리오 1개와 입력·출력 대상을 선정한다.
- MCU, 부품, 통신 장비의 보유·조달 가능 여부를 확인한다.
- 입출력 핀, 전압 조건, 시스템 연결 관계를 정리한다.
- 제어 주기, 상태 보고 주기, 응답 시간, 반복 시험 횟수의 목표를 정한다.
- 오류 시 출력 상태와 복구 조건, 필수 기능과 확장 기능을 구분한다.
- 실제 일정과 담당자를 확정한다.

**산출물:** 요구사항 목록, 부품 목록, 시스템 구성도, 측정 가능한 완료 기준.  
**완료 기준:** 최소 시연 범위와 필요한 장비·시험 방법이 정해져 2주차 작업을 시작할 수 있다.

## 2주차 — 개발 환경 및 기본 구동

- 선정한 IDE·컴파일러·SDK의 버전을 기록한다.
- 기본 프로젝트를 생성하고 빌드·다운로드·디버깅을 확인한다.
- 기본 GPIO와 사용 가능한 로그 출력 수단을 확인한다.
- 초기화 순서와 핀 설정을 기록한다.

**산출물:** 기본 펌웨어, 환경 설정 및 빌드·다운로드 안내, 구동 로그.  
**완료 기준:** 문서 절차로 펌웨어를 다시 빌드·다운로드하여 기본 입출력을 확인한다.

## 3주차 — 입력 수집 및 출력 제어

- 선정한 입력 장치의 값을 읽고 정상 범위를 정의한다.
- 선정한 출력 장치를 제어하고 입력과 출력의 대응 관계를 구현한다.
- 하드웨어 접근과 제어 로직을 구분한다.
- 정상값·경계값·유효하지 않은 입력의 처리 방법을 시험한다.

**산출물:** 입출력 모듈, 핀 연결표, 단위 동작 시험 기록.  
**완료 기준:** 사전에 정의한 입력 조건에서 기대한 출력이 나오고, 입력 오류 처리 결과가 기록된다.

## 4주차 — 외부 통신

- 선정한 인터페이스를 연결하고 메시지 ID 또는 명령, 데이터 길이·단위·범위를 정의한다.
- 외부 명령 수신과 MCU 상태 송신을 구현한다.
- 잘못된 명령·길이·값에 대한 처리 방법을 정의한다.
- PC 도구 또는 상위 장치로 송수신을 시험한다.

**산출물:** 메시지 규격, 통신 모듈, 정상·비정상 메시지 시험 기록.  
**완료 기준:** 정의한 명령과 상태 메시지가 양방향으로 전달되며, 잘못된 메시지의 처리 동작을 확인한다.

## 5주차 — 상태 관리 및 기능 통합

- 초기화·대기·동작·오류 상태와 전이 조건을 정의한다.
- 입력, 외부 명령, 제어 출력 및 상태 보고를 연결한다.
- 실행 구조에 맞게 처리 순서·주기를 구성한다.
- RTOS를 채택한 경우 태스크 역할·주기·공유 데이터 접근 방식을 기록한다.

**산출물:** 상태 전이표, 통합 펌웨어, 대표 시나리오 실행 기록.  
**완료 기준:** 외부 명령에서 출력과 상태 보고까지 이어지는 기본 시나리오와 정의한 상태 전이를 확인한다.

## 6주차 — 오류 대응 및 주기 검증

- 통신 중단, 유효하지 않은 입력 등 선정한 오류를 재현한다.
- 타임아웃과 오류 상태 전이, 정해진 출력 상태, 복구 동작을 구현·검증한다.
- 입력·제어·상태 보고 주기와 명령 응답 시간을 측정한다.
- 1주차 목표와 비교하고 초과 항목의 원인을 수정하거나 제약으로 기록한다.

**산출물:** 오류 시험 결과, 주기·응답 시간 측정 결과, 수정 내역.  
**완료 기준:** 합의한 오류 대응과 시간 목표를 충족한다. 미달 항목은 해결 전까지 미완료로 유지한다.

## 7주차 — 통합 시험 및 시연 안정화

- 정상·경계·오류·복구 시험을 통합 시험표로 정리한다.
- 합의한 횟수만큼 대표 시나리오를 반복 실행한다.
- 재부팅과 통신 재연결 후 동작을 확인한다.
- 시연을 막는 결함을 수정하고 영향을 받은 시험을 다시 수행한다.
- 기능 추가를 제한하고 최종 시연 순서를 정리한다.

**산출물:** 통합 시험표, 결함 목록 및 수정·재시험 결과, 시연 시나리오.  
**완료 기준:** 필수 시험이 통과하고 시연을 막는 결함이 해결되며 남은 제약이 문서화된다.

## 8주차 — 최종 시연 및 결과 정리

- 기록한 환경과 절차로 빌드·다운로드·실행을 다시 확인한다.
- 시연 영상 또는 사진과 실행 로그를 정리한다.
- 구현 범위, 설계 선택, 시험 결과, 제한 사항, 개선 방향을 작성한다.
- README에 검증된 설치·실행 안내와 결과 자료 링크를 반영한다.

**산출물:** 최종 펌웨어, 재현 안내, 시연 자료, 결과 보고.  
**완료 기준:** README의 최종 완료 항목을 증거와 함께 점검하고, 미완료 기능은 구현 결과와 구분해 표시한다.

## 일정 조정 기준

- 부품 조달이 늦어지면 메시지 규격·상태 로직·시험 절차 작성을 먼저 진행한다. 모의 시험과 실제 하드웨어 시험 결과는 구분한다.
- 일정이 부족하면 최소 입력·출력 1종과 명령·상태 통신에 집중하고, 확장 기능을 후속 작업으로 옮긴다.
- 선행 주차의 완료 기준을 충족하지 못하면 원인과 영향을 기록하고 후속 일정·범위를 조정한다.
- 보드·인터페이스·시나리오가 바뀌면 연결도, 메시지 규격 및 관련 시험 항목을 함께 갱신한다.
