# SDV_MCU_Project

SDV(Software Defined Vehicle) 환경을 가정한 MCU 기반 제어·통신 프로젝트의 초기 기획 저장소입니다.

> **문서 상태: v0.1 / 제안 초안 (2026-09-08)**  
> 저장소명을 바탕으로 SDV를 Software Defined Vehicle로 해석했습니다. 아래 목표·기능·4주 일정은 논의를 위한 제안이며, 확정된 요구사항이나 구현 완료 내역이 아닙니다. 개발 기간은 4주이며, 보드, 제어 대상, 통신 방식 및 실제 날짜는 1주차에 확정합니다.

## 1. 프로젝트 목적

MCU에서 입력 수집, 상태 판단, 출력 제어, 외부 명령 수신 및 상태 보고가 이어지는 작은 시스템을 구현하고 검증하는 것을 목표로 합니다. 재현 가능한 빌드·실행 방법과 시험 결과도 함께 관리합니다.

## 2. 초기 구현 범위 (제안)

| 구분 | 제안 내용 | 완료 기준 |
|---|---|---|
| 기본 구동 | MCU 개발 환경 구성 및 기본 입출력 확인 | 예제 빌드·다운로드·실행 재현 |
| 입력과 제어 | 입력 1종 이상을 읽어 출력 1종 이상 제어 | 정의한 정상 입력에서 기대 출력 확인 |
| 상태 관리 | 초기화·대기·동작·오류 상태 정의 | 상태 전이 조건별 시험 통과 |
| 외부 통신 | 명령 수신 및 상태 보고 | 정상 명령과 잘못된 명령 처리 확인 |
| 예외 처리 | 통신 끊김·잘못된 입력 등 정의한 오류 대응 | 오류 시 정해진 출력 상태 및 복구 확인 |
| 통합 시연 | 명령 → 상태 전이 → 출력 → 상태 보고 | 대표 시나리오 반복 실행 결과 기록 |

실제 차량 적용을 전제로 하지 않는 개발 보드 기반 시제품을 제안합니다. OTA, 다중 ECU, AUTOSAR 등 확장 기능은 기본 시연 완료 후 필요성과 일정을 검토합니다.

## 3. 시스템 구성 (초안)

```text
PC / 상위 제어 장치
        ↕ 명령 및 상태 메시지 (인터페이스 미정)
MCU: 통신 처리 → 상태 판단 → 출력 제어
                         ↑
                    입력 수집
```

통신 처리, 상태 로직, 하드웨어 입출력을 구분하는 구조를 목표로 합니다. RTOS 도입 여부와 태스크 구성은 요구 주기 및 동시 처리 필요성을 확인한 뒤 결정합니다.

## 4. 확정할 사항

| 항목 | 현재 상태 |
|---|---|
| 프로젝트 시나리오 및 제어 대상 | 미정 — 입력·출력 각 1종의 최소 시나리오부터 선정 |
| MCU / 개발 보드 | 미정 |
| 센서·출력 장치 및 부품 | 미정 |
| 언어 / IDE / 툴체인 | 미정 |
| 실행 구조 | 미정 — Bare-metal 또는 RTOS 검토 |
| 통신 인터페이스 | 미정 — CAN, UART 등의 후보 중 요구사항·장비에 따라 선택 |
| 입력·제어·상태 보고 주기 | 미정 — 1주차에 측정 가능한 수치로 정의 |
| 오류 시 출력 상태 및 복구 조건 | 미정 — 제어 대상 선정 후 정의 |
| 시작일 / 최종 마감일 / 담당자 | 미정 |
| 일정 | 총 4주 — 실제 시작일과 마감일은 미정 |

## 5. 주차별 계획 요약

| 주차 | 목표 | 주요 산출물 |
|---|---|---|
| 1주차 | 요구사항·환경 구축 및 기본 구동 | 요구사항, 부품·핀 목록, 빌드 안내, 기본 구동 로그 |
| 2주차 | 입력·출력 및 외부 통신 구현 | 입출력·통신 모듈, 메시지 규격, 개별 시험 기록 |
| 3주차 | 상태 관리·통합 및 오류 처리 | 통합 펌웨어, 상태 전이표, 오류·주기 시험 결과 |
| 4주차 | 최종 검증·시연 및 문서 정리 | 통합 시험표, 재현 안내, 시연 자료, 결과 보고 |

상세 작업과 주차별 완료 기준은 [주차별 계획](docs/WEEKLY_PLAN.md)을 참고합니다.

## 6. 최종 완료 기준 (초안)

- [ ] 보드·부품·핀 연결·툴체인 버전이 문서화되어 있다.
- [ ] 문서에 따라 빌드, 펌웨어 다운로드, 실행을 재현할 수 있다.
- [ ] 입력 → 제어 → 출력 및 외부 명령 → 상태 보고 시나리오가 동작한다.
- [ ] 합의한 제어·통신 주기 목표를 측정으로 확인한다.
- [ ] 합의한 오류 상황에서 출력 상태와 복구 동작을 검증한다.
- [ ] 시험 조건, 기대 결과, 실제 결과 및 남은 제약을 기록한다.
- [ ] 최종 시연 자료와 결과 보고를 정리한다.

정량 목표와 반복 횟수는 1주차에 확정하며, 현재 체크 항목은 모두 미완료입니다.
